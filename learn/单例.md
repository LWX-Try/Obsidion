单例模式（Singleton Pattern）的核心目标是：<font color="#ff0000">保证一个类只有一个实例，并提供一个全局访问点。</font>

# 饿汉式：
```C++
//单例：饿汉式。
class Singleton
{
public:
    static Singleton* getSingleton()
    {
        return m_p_instance;
    }
    Singleton(const Singleton&)=delete;
    Singleton& operator=(const Singleton&)=delete;

private:
    Singleton()=default;
    ~Singleton()=default;

    static Singleton* m_p_instance;
};
Singleton* Singleton::m_p_instance=new Singleton();
//在类外，初始化类内的静态成员的时候，可以使用构造函数。
//private限制的是外部代码（类外部的函数、其他类）不能调用。
//不限制类自己的成员函数和静态成员。
```
- **优点**：<font color="#ff0000">线程安全</font>（在 main 之前初始化，不存在多线程竞争），实现简单。
- **缺点**：提前占用内存（可能一直用不到），且存在**静态初始化顺序问题**（跨编译单元调用时可能拿到未初始化的指针）。

# 懒汉式：
```C++
//单例：懒汉式
class Singleton
{
public:
    static Singleton* getSingleton()
    {
        if(!m_p_instance)
        {
            m_p_instanc=new Singleton;
        }
        return m_p_instanc;
    }
    Singleton(const Singleton&)=delete;
    Singleton& operator=(const Singleton&)=delete;

private:
    Singleton()=default;
    ~Singleton()=default;
    
    static Singleton* m_p_instanc;
};
Singleton* Singleton::m_p_instanc=nullptr;
```
- **优点**：延迟加载，节省资源。
- **缺点**：<font color="#ff0000">多线程不安全。</font>多个线程同时判断为空，会 `new` 出多个对象，造成内存泄漏和单例失效。

# 懒汉式+互斥锁（线程安全版）：
```C++
//单例：懒汉式+互斥锁（线程安全）
class Singleton
{
public:
    static Singleton* getSingleton()
    {
        lock_guard<mutex> lock(m_mutex);    //构造时自动加锁。
        if(!m_p_instance)
        {
            m_p_instanc=new Singleton;
        }
        return m_p_instanc;                 //离开时，lock析构，自动解锁。
    }

    Singleton(const Singleton&)=delete;
    Singleton& operator=(const Singleton&)=delete;
private:
    Singleton()=default;
    ~Singleton()=default;

    static mutex m_mutex;
    static Singleton* m_p_instanc;
};
mutex Singleton::m_mutex;
Singleton* Singleton::m_p_instanc=nullptr;

//lock_guard类：
构造时：调用 mtx.lock()。
析构时：调用 mtx.unlock()。
即使临界区抛异常，也能保证解锁。
不能拷贝，不能移动，不能手动 unlock。
```
- **优点**：线程安全。
- **缺点**：每次调用 `getInstance()` 都要加锁解锁，<font color="#ff0000">并发性能极差</font>。实际上大多数时候只是读取，根本不需要加锁。
- <font color="#ff0000">lock_guard的生命周期，就是他的作用域。</font>

# 双检锁：
```C++
// 双检锁
class Singleton
{
public:
    static Singleton *getSingleton()
    {
        if (!m_p_instance)                       //首次检查。
        {
            lock_guard<mutex> lock(m_mutex);    //进到里面，进行上锁。
            if (!m_p_instanc)                   //再次检查。
            {
                m_p_instanc = new Singleton;
            }
        }
        return m_p_instanc;
    }
    
    Singleton(const Singleton &) = delete;
    Singleton &operator=(const Singleton &) = delete;
    
private:
    Singleton() = default;
    ~Singleton() = default;
    
    static mutex m_mutex;
    static Singleton *m_p_instanc;
};
mutex Singleton::m_mutex;
Singleton *Singleton::m_p_instanc = nullptr;
```
- **特点**：第一次检查不加锁，为空才加锁，再检查一次。
- **优点**：兼顾了延迟加载和线程安全，性能较好。
- **缺点（历史大坑）**：在 C++11 之前，`m_p_single = new Singleton()` 可能会因为**指令重排**（先分配内存地址，再执行构造）导致其他线程拿到一个半成品对象。C++11 后需要配合 `std::atomic` 和内存屏障才能完全安全。**实现极度复杂，容易写错。**

# call_once + unique_ptr：
```C++
class Singleton
{
public:
    static Singleton& getSingleton()
    {
        call_once(m_onceFlag, []()
                  { m_p_instance.reset(new Singleton{}); });
        return *m_p_instance;
    };

    Singleton(const Singleton &) = delete;
    Singleton &operator=(const Singleton &) = delete;
    
private:
    Singleton() = default;
    ~Singleton() = default;

    static unique_ptr<Singleton> m_p_instance;
    static once_flag m_onceFlag;
};
unique_ptr<Singleton> Singleton::m_p_instance;
once_flag Singleton::m_onceFlag;
```
- **优点**：线程安全，且利用 `unique_ptr` 在程序结束时**自动释放内存**，不需要手动写 `destroy()`。
- **缺点**：代码依然略长，且需要类外定义静态成员。

# Meyers' Singleton（梅耶斯单例）：
```C++
class Singleton
{
public:
    static Singleton &getSingleton()
    {
        static Singleton m_instance; // 局部静态变量（分配在全局静态存储区）。
        return m_instance;
    }

    Singleton(const Singleton &) = delete;
    Singleton &operator=(const Singleton &) = delete;
    
    ~Singleton() = default;     //需要把析构函数设为public。
private:
    Singleton() = default;
};
```
- 最优解。
- 析构函数设为public。
  静态局部变量由编译器管理释放。所以当程序结束时，编译器自动调用对象的析构函数。所以把析构函数设为public。
