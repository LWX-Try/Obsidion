## 5.1：友元
---
友元就是访问类中的私有成员。使用friend关键字声明友元。
友元的三种形式：普通函数，成员函数，友元类
### 5.1.1：普通函数
再类外定义一个新的函数，但是这个函数需要访问某个类中的私有成员。
这时，在这个类中，声明这个函数的友元，然后就可以再函数中使用了。
```C++
class MyClass
{
public:
    MyClass(){}
    MyClass(int data)
    :m_data(data)
    {}
    // 声明友元函数
    friend void friendFunc(const MyClass & cls);

private:
    int m_data;
    void privateFunc()
    {
        cout << "privateFunc" << endl;
    }
    // const函数由const对象访问
    void privateFunc() const
    {
        cout << "const privateFunc" << endl;
    }
};

// 使用了const
void friendFunc(const MyClass & cls)
{
    // 友元函数访问类中私有成员
    cout << cls.m_data << endl;
    cls.privateFunc();
}

void test1(){
    const MyClass cls2 {1};
    friendFunc(cls2);
}
```
### 5.1.2：成员函数
假设A类中有一个成员函数，这个成员函数需要访问B类中的私有变量，可以在B类中声明这个成员函数的友元。
注意:
1. 需要把B类前向声明,否则在A类中不知道B类的存在
2. 需要在A类中给出成员函数的声明,函数的定义即具体实现写在类外,此时编译器只知道B类的存在,但是不知道具体实现.
```C++
//前向声明 : 让编译器认识MyClass类
class MyClass;

class FriendClass
{
public:
    void display(MyClass & cls); 
};

class MyClass
{
public:
    MyClass(){}
    MyClass(int data)
    :m_data(data)
    {}
    // 成员函数作为友元声明
    friend void FriendClass::display(MyClass & cls);

private:
    int m_data;
    void privateFunc()
    {
        cout << "privateFunc" << endl;
    }
};

void FriendClass::display(MyClass & cls)
{
    cout << cls.m_data << endl;
    cls.privateFunc();
}

void test1()
{
    FriendClass cls {};
    MyClass myClass {20};
    cls.display(myClass);
}

int main(int argc, char *argv[])
{
    test1();
    return 0;
}
```
补充：
前向声明的用处：进行了前向声明的类，可以以引用或指针的形式作为函数的参数，只要不涉及到对该类对象具体成员的访问，编译器可以通过。
### 5.1.3：友元类
如上的例子，假设类 A中不止有一个 成员函数，还有其他成员函数，它们都需要访问B类 的私有成员，如果还像上面的方式一个一个设置友元，就比较繁琐了，可以直接将 A类设置为 B 的友元类，在工作中这也是更常见的方法。
```C++
// B类
class MyClass
{
public:
    MyClass(){}
    MyClass(int data)
        :m_data(data)
    {}
    // FriendClass类作为友元声明
    friend class FriendClass; 
private:
    int m_data;
    void privateFunc()
    {
        cout << "privateFunc" << endl;
    }
};
// A类
class FriendClass
{
public:
    void display(MyClass & cls)
    {
        cout << cls.m_data << endl;
        cls.privateFunc();
    }
    
    void display2(MyClass & cls)
    {
        cout << cls.m_data << endl;
        cls.privateFunc();
    }

};

void test1()
{
    FriendClass cls {};
    MyClass myClass {20};
    cls.display(myClass);
    cls.display2(myClass);
}

int main(int argc, char *argv[])
{
    test1();
    return 0;
}
```
### 5.1.4：友元特点
1. **友元不受类中访问权限的限制**——可访问私有成员
2. **友元破坏了类的封装性**
3. **不能滥用友元 ，友元的使用受到限制**
4. **友元是单向的**——A类是B类的友元类(B中声明A为friend class)，则A类成员函数中可以访问B类私有成员；但并不代表B类是A类的友元类，如果A类中没有声明B类为友元类，此时B类的成员函数中并不能访问A类私有成员
5. **友元不具备传递性**——A是B的友元类，B是C的友元类，无法推断出A是C的友元类
6. **友元不能被继承**——因为友元破坏了类的封装性，为了降低影响，设计层面上友元不能被继承
## 5.2：运算符重载
---
能够重载的运算符有42个：
![[可重载运算符.png]]
不能重载的运算符有5个：
- `.` 成员访问运算符
- `.*`成员指针访问运算符
- `?:`三目运算符
- `::`作用域限定符
- `sizeof`长度运算符

记法：**带点的运算符不能重载，加上sizeof**。只要带"."，带“:“，和sizeof，不能重载。

### 5.2.1：运算符重载的规则和形式
- **运算符重载有以下规则**
1. 运算符重载时 ，**其操作数类型必须要有自定义类类型或枚举类型** ——不能全都是内置类型
2. 运算符重载的本质是函数重载, 其优先级和结合性还是固定不变的 a == b + c
3. **操作符的操作数个数是保持不变的**
4. **运算符重载时 ，不能设置默认参数** ——如果设置了默认值，其实也就是改变了操作数的个数
5. 逻辑与 && 逻辑或 || 就不再具备短路求值特性 ，进入函数体之前必须完成所有函数参数的计算, 不推荐重载
6. 不能臆造一个并不存在的运算符 @ $ 、

### 5.2.2：重载的实现
- **运算符重载的形式**
运算符重载的形式有三种：
1. **采用友元函数的重载形式**
2. 采用普通函数的重载形式
3. **采用成员函数的重载形式**

倾向于友元方式的重载：+，>>，<<。
因为不会修改操作数的值的运算符。

倾向于成员函数形式的重载：+=，前置++，后置++，[ ]。
因为会修改操作数的值。

这里以+运算符重载为例。
#### +运算符重载
友元函数实现：
```C++
class Complex
{
    //...
    friend Complex operator+(const Complex & lhs, const Complex & rhs);
    //...
};

Complex operator+(const Complex & lhs, const Complex & rhs)
{
    //...
}

void test0()
{
    Complex cx(1,2);
    Complex cx2(3,4);
    Complex cx3 = cx + cx2; //看上去和内置类型的计算一样了
    //Complex cx3 = operator(cx,cx2);   //本质上是调用了operator+函数
}
```

**运算符重载的本质是定义一个运算符重载函数，定义的步骤如下**
1. 先确定这个函数的返回值是什么类型（加法运算返回值应该是一个临时的Complex对象，所以此处返回类型为Complex）
2. 再写上函数名（operator + 运算符，此处就是**operator+**）
3. 再补充参数列表（考虑这个运算符有几个操作数，此处加法运算应该有两个操作数，分别是两个Complex对象，因为加法操作不改变操作数的值，可以用const引用作为形参）
4. 最后完成函数体的内容（此处直接调用Complex构造函数创建一个新的对象作为返回值）。
——在定义的operator+函数中需要访问Complex类的私有成员，要进行友元声明
<font color="#ff0000">像 + 这一类不会修改操作数的值的运算符，倾向于采用友元函数的方式重载。</font>

普通函数实现：
**实际工作中不推荐使用，因为这样做几乎完全失去了对私有成员的保护。**
```C++
class Complex 
{
public:
	//...
	double getReal() const { return m_real; }
	double getImage() const { return m_image; }
	//...
};

Complex operator+(const Complex & lhs, const Complex & rhs)
{
	return Complex(lhs.getReal() + rhs.getReal(),
			lhs.getImage() + rhs.getImage());
}

void test0()
{
	Complex c1(1, 2), c2(3, 4);
	Complex c3 = c1 + c2;//ok
}
```

成员函数实现：
```C++
class Complex
{
public:
	//...
	Complex operator+(const Complex & rhs)
	{
		return Complex(m_real + rhs.m_real, m_image + rhs.m_image);
	}
};
```

#### +=运算符重载
<font color="#ff0000">像+=这一类会修改操作数的值的运算符，倾向于采用成员函数的方式重载。</font>
```C++
class Complex
{
public:
    Complex(int real, int image)
    : m_real(real)
    , m_image(image)
    {}        

    Complex & operator+=(const Complex & com)
    {
        this->m_real = this->m_real + com.m_real;
        this->m_image = this->m_image+ com.m_image;
        return *this;
    }
    void print()
    {
        cout << m_real << "+" << m_image << "i" << endl;
    }

private:
    int m_real;
    int m_image;
};
```

#### ++运算符重载
++运算符的重载，分为 前置++ 和 后置++。

优先使用前置++，因为这样效率高。后置++有拷贝。
<font color="#ff0000">++a是左值，可以取地址。&（++a），先在a内存里面进行++，再对这个值取地址。</font>
<font color="#ff0000">a++是右值，不可以取地址。&（a++），先在a里面进行拷贝取值，再++计</font>算。是右值。

```C++
void test0()
{
    // 以内置类型为参考
    int a = 1;
    &(++a); // OK 左值
    /* &(a++); error 右值 是个临时变量*/
}

//前置++的形式
Complex& operator++()
{
    cout << "Complex & operator++()" << endl;
    ++m_real;
    ++m_image;
    return *this;
}

//后置++的形式
//参数列表中要多加一个int
//与前置形式进行区分
Complex operator++(int)
{
    cout << "Complex operator++(int)" << endl;
    //通过拷贝构造 把当前对象的数据成员初始化一个新对象
    Complex tmp(*this);
    ++m_real;
    ++m_image;
    // 返回新对象
    return tmp;
}

void test1()
{
    Complex c1 = Complex{1,1};
    /* Complex c2 = ++c1; */
    Complex c2 = c1++;
    c2.print();
    c1.print();
}

```
<font color="#ff0000">后置++中参数列表中的 `int` 并不需要一个具体的变量名，它只是用来区分前置和后置运算符的。</font>这个 `int` 参数的存在是为了符合运算符重载的语法要求，而它实际上并不被使用,这个参数的实际作用是作为一个占位符，告诉编译器这是后置版本的自增

#### \[ ]运算符重载
`Type & operator[](size_t index); // size_t无符号`
```C++
class CharArray
{
public:
    //constructor
    CharArray(const char * str)
    : m_capacity(strlen(str))
    , m_data(new char[strlen(str) + 1]{})
    {
        strcpy(m_data, str);
    }
    //destructor
    ~CharArray()
    {
        if(m_data)
        {
            delete [] m_data;
            m_data = nullptr;
        }
    }
    // operator []  重载
    char & operator[](size_t index)
    {
        // 判断下标是否越界
        if(index >= m_capacity)
        {
            cout << "index out of range" << endl;
            static char nullChar = '\0';
            return nullChar;
        }
        else
        {
            // 返回下标位置的字符
            return m_data[index];
        }
    }
    void print()
    {
        cout << m_data << endl;
    }
private:
    int m_capacity;// 数组容量
    char * m_data;// 数组指针
};

void test1()
{
    CharArray ch {"hello"};
    cout << ch[0] << endl;
    ch[0] = 'H';
    cout << ch[0] << endl;
    ch.print();
}
```

#### 成员访问运算符
成员访问运算符包括 . 和 -> ，其中 . 这个运算符是不能重载的。->是可以重载的。
->运算符，<font color="#ff0000">只能以成员函数的形式进行重载</font>，返回值必须是一个<font color="#ff0000">指针</font>或者重载了箭头运算符的<font color="#ff0000">对象</font>。
- 两层结构下的使用
- 三层结构下的使用（难点）
- 内存分析
1：两层结构下的使用
```C++
class Data
{
public:
    Data(){}
    ~Data(){}

    int getData() const{ return m_data; }
private:
    int m_data = 10;
};

class MiddleLayer
{
public:
    MiddleLayer(Data * p)
    : m_pData(p)
    {}

    ~MiddleLayer()
    {
        if(m_pData)
        {
            delete m_pData;
            m_pData = nullptr;
        }
    }
private:
    Data * m_pData;
};
```
用这种方式创建MiddleLayer对象，我们发现不需要手动delet pdata，并没有发生内存泄露，反而手动delet pdata后会有double free的问题
![[两层结构重载_1.png]]
当然，也可以让Middlelayer对象自己管理一个Data对象
![[两层结构重载_2.png]]
箭头运算符无法应对MiddleLayer对象，那么可以定义箭头运算符重载函数。

要重载 `->` 运算符，需要在类中定义 `operator->` 成员函数。这个成员函数的返回值通常是一个**指针**，该指针指向内部对象或封装的其他类的对象。

**返回类型**：`operator->` 必须返回一个指针，因为 `->` 运算符会继续对返回的指针进行成员访问, 编译器会自动递归调用`operator->()`直到得到原生指针。
```C++
Data * operator->()
{
    return m_pData;
}
```

要重载解引用运算符 `*`，需要在类中定义 `operator*` 成员函数。通常返回一个对内部封装对象的引用，这样用户就可以像使用普通指针一样访问内部对象的成员。
- **返回类型**：通常是一个引用 (`Type &`)，这样可以允许对对象的直接修改。
- 如果要确保支持 `const` 对象，可以提供一个常量版本的 `operator*()`。
```C++
// *解引用重载
Data & operator*()
{
    return *m_pData;
}
```
![[两层结构示意图.png]]
- 重载 `*` 解引用运算符的目的是使类对象可以表现得像指针一样，通过解引用访问封装的对象。
- 重载 `*` 通常用于实现类似智能指针的类，返回内部封装对象的引用。

2：三层结构下的使用（难点）
```C++
class ThirdLayer
{
public:
    ThirdLayer(MiddleLayer *ml)
    :m_pml(ml)
    {
        cout << "ThirdLayer constructor" << endl;
    }
    ~ThirdLayer()
    {
        cout << "ThirdLayer destructor" << endl;
        if(m_pml){
            delete m_pml;
            m_pml = nullptr;
        }
    }
private:
    MiddleLayer *m_pml;
};
```
**注意：应该让ThirdLayer底层的指针管理一个堆上的MiddleLayer对象**
![[三层结构重载.png]]
```C++
// 在MiddleLayer重载的operator->函数作为铺垫
// 只需要返回MiddleLayer对象即可
// ->重载
MiddleLayer & operator->()
{
 return *m_pml;
}
// *重载

 return *m_pml;
}
```
使用时，就这样使用：
```C++

// 解引用使用
cout << (*(*tl)).getData() << endl;
// 本质 同过*重载得到MiddleLayer对象后再解引用得到Data对象
cout << tl.operator*().operator*().getData() << endl;

// ->使用
cout << tl->getData() << endl;
// 本质 链式调用
cout << tl.operator->().operator->()->getData() << endl;
```

## 5.3：可调用实体
---
### 5.3.1：函数对象
一个行为类似于函数的对象, 它的作用是在代码中能够像函数一样调用，但是它其实是一个类的实例。
```C++
class FunctionObject
{
    //...
    // 重载函数调用运算符
    ReturnType operator()(ParameterList)
    {
        // do something....
    }
};

void test0()
{
    FunctionObject fo{ };
    fo();  //让对象像一个函数一样被调用
}
```
上面的代码看起来很奇怪，如果我们从运算符的视角出发，就是函数调用运算符()要处理FunctionObject对象，只需要实现一个**函数调用运算符重载**函数即可。

**重载了函数调用运算符的类的对象称为函数对象**，由于参数列表可以随意扩展 ，所以可以有很多重载形式（对应了普通函数的多种重载形式）。
```C++
class FunctionObject
{
public:
    void operator()()
    {
        cout << "operator()" << endl;
    }
    int operator()(int x, int y)
    {
        cout << "operator(int, int)" << endl;
        return  x + y;
    }
    double operator()(double x, double y, double z)
    {
        cout << "operator(double, double, double)" << endl;
        return  x + y + z;
    }

};

void test1()
{
    FunctionObject fo = FunctionObject{};
    // 函数调用运算符来处理fo对象的使用
    fo();
    cout << fo(1,2) << endl;
    cout << fo(1.1, 2, 3.3) << endl;
}
```

函数对象相比普通函数的优点：
可以携带状态（函数对象可以封装自己的数据成员、成员函数，具有更好的面向对象的特性）。
可以记录函数对象被调用的次数，而普通函数只能通过全局变量做到（全局变量不够安全）。
### 5.3.2：函数指针
本质是一个指针，指向函数的指针。
例子如下：
```C++
void print(int x)
{
    cout << "print:" << x << endl;
}

void display(int x)
{
    cout << "display:" << x << endl;
}

int main(void)
{
    //省略形式
    void (*p)(int) = print;
    p(4);
    p = display;
    p(9);
    
    //完整形式
    void (*p2)(int) = &print;
    (*p2)(4);
    p2 = &display;
    (*p2)(9);
}
```
以前我们使用typedef可以定义类型别名，这段程序中函数指针p、p2的类型是void (\*) (int)，但是C++中是没有这个类的（我们可以这样理解，但是代码不能这么写）

可以使用typedef定义这样的一个新类型

可以理解为是给void ( * ) (int) 取类型别名为Function
`typedef void(*Function)(int);`
```C++
Function f;
// 指向print函数
f = print;
// 调用print函数
f(19);
// 指向display函数
f = display;
// 调用display函数
f(27);
```
### 5.3.3：成员函数指针
本质上是一个指针，指向类中的成员函数。
```C++
//C++风格的类型别名
using MemberFunction = void (FFF::*)(int);

//C风格的类型别名
typedef void (FFF::*MemberFunction)(int);
```
<font color="#ff0000">调用它时，必须绑定一个具体的对象，因为非静态成员函数内部需要 this 指针。</font>
有FFF这样的一个类，里面包含两个成员函数。
```C++
class FFF
{
public:
    void print(int x)
    {
        cout << "FFF::print:" << x << endl;
    }

    void display(int x)
    {
        cout << "FFF::display:" << x << endl;
    }
};
```
定义一个函数指针要明确指针指向的函数的返回类型、参数类型，那么**定义一个成员函数指针还需要确定的是这个成员函数是哪个类的成员函数（类的作用域）**
```C++
// 声明成员函数指针:
返回类型 (类名::*指针名称)(参数列表);

//将成员函数指针指向特定的成员函数：
指针名称 = &类名::成员函数;

class MyClass 
{
public:
    void show(int x) { cout << x << endl; }
};

// 定义：必须写类名 MyClass::*
void (MyClass::*mfp)(int) = &MyClass::show;

// 调用：必须绑定对象
MyClass obj;
(obj.*mfp)(10);               // 用对象调用
MyClass* p = &obj;
(p->*mfp)(10);                // 用指针调用
```
与普通函数指针不一样的是，**成员函数指针的定义和使用都需要使用完整写法**，不能使用省略写法，定义时要完整写出指针声明，使用时要完整写出解引用（解出成员函数后接受参数进行调用）。

另外，成员函数需要通过对象来调用，**成员函数指针也需要通过对象来调用**。

**数指针的意义：**
1. 回调函数：**将成员函数指针作为参数传递给其他函数**，使其他函数能够在特定条件下调用该成员函数；
2. 事件处理：将成员函数指针存储事件处理程序中，以便在特定事件发生时调用相应的成员函数；
3. 多态性：通过将成员函数指针存储在基类指针中，可以实现多态性，在运行时能够去调用相应的成员函数。

### 5.6.3：方式三：atexit + destory
懒汉式：只有在调用的时候，才会生成的单例对象。
饿汉式：程序启动的时候，就会生成单例对象。
```C++
//对于ms_pInstance的初始化有两种方式

//饱汉式（懒汉式）—— 懒加载，不使用到该对象，就不会创建
Singleton* Singleton::ms_pInstance = nullptr; 

//饿汉式 —— 最开始就创建（即使不使用这个单例对象）
Singleton* Singleton::ms_pInstance = Singleton::getInstance();
```
但是还遗留了一个问题，就是以上几种方式都无法解决**多线程安全**问题。
当多个线程同时进入if语句时，会造成单例对象被创建出多个，但是最终只有一个地址值会由ms_pInstance指针保存，因此造成内存泄漏。

可以使用**饿汉式解决**，但同时也可能带来内存压力（即使不用单例对象，也会被创建）

饿汉式可以确保getInstance函数的第一次调用一定是在ms_pInstance的初始化时，之后再调用getInstance函数的时候,都不会进入if分支创建出对象。

atexit()函数：
atexit( 函数指针 ) , 当程序结束时,想要执行的函数或者操作,可以注册到atexit函数中
```C++
#include <iostream>
#include <cstdlib>   // atexit
#include <mutex>

class Singleton 
{
private:
    Singleton() { std::cout << "Singleton 构造\n"; }
    ~Singleton() { std::cout << "Singleton 析构\n"; }

    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;

    static Singleton* instance;
    static std::mutex mtx;

    // 静态清理函数，供 atexit 注册。
    //要把destroy()函数设为私有，防止被调用。
    static void destroy() 
    {
        if (instance) 
        {
            delete instance;
            instance = nullptr;
            std::cout << "destroy: 单例已释放\n";
        }
    }

public:
    static Singleton* getInstance() 
    {
        if (instance == nullptr) 
        {               
            instance = new Singleton();
            // 注册清理函数，只注册一次（因为只有第一次创建时才进入这里）
                
            if (std::atexit(destroy) != 0) 
            {
                std::cerr << "atexit 注册失败\n";
            }
        }
        return instance;
    }
};

// 静态成员定义：这里使用的是懒汉式。可能发生多线程内存泄漏。
Singleton* Singleton::instance = nullptr;

int main() {
    Singleton* s1 = Singleton::getInstance();
    Singleton* s2 = Singleton::getInstance();
    std::cout << "s1 == s2: " << (s1 == s2) << "\n";

    return 0;   // 程序正常退出，atexit 调用 destroy
}
```
### 5.6.4：方式四：atexit+pthread_once+destory
pthread_once函数可以确保初始化代码只会执行一次, 无论在多少个线程中调用它。
传给pthread_once函数的第一个参数比较特殊，形式固定；第二个参数需要是一个`静态函数指针`，pthread_once可以确保这个函数只会执行一次。
```C++
class Singleton
{
public:

    static Singleton * getInstance()
    {
        pthread_once(&m_once_control, &initRoutine);
        return m_pInstance;
    }

    // 定义一个初始化的函数 必须要是static函数
    static void initRoutine()
    {
        // 初始化的操作
        m_pInstance = new Singleton{};
        
        // destroy注册到atexit中
        if(0 != atexit(&destroyInstance));
        {
            std::cerr << "atexit 注册失败\n";
        }
    }

    // 删除复制控制的函数
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;

    // 提供一个释放资源的操作
    static void destroyInstance()
    {
        cout  << "destroy " << endl;
        if(m_pInstance){
            delete m_pInstance;
            m_pInstance = nullptr;
        }
    }
private:
    // 构造函数私有化
    Singleton(){}
    // satic自身类型的指针
    static Singleton * m_pInstance;

    // 固定值
    static pthread_once_t m_once_control;
```

## 5.7：std::string的底层实现（重要）

- COW（Copy-On-Write 写时复制）
- SSO(Short String Optimization 短字符串优化)
### 5.7.1：COW的原理
- 共享数据：当多个对象（如字符串变量）引用同一份数据时，它们共享底层内存，而非立即复制。
- 延迟复制：只有在某个对象尝试修改数据时，系统才会创建该数据的独立副本，确保修改不影响其他共享对象。

COW只有在拷贝构造函数，赋值运算符中，才会使用。
意思就是，如果创建两个string变量，这两个变量的内容是一样，不一定会触发COW。
例如，下面的就不是COW，：
```C++
string s1("hello");
//在创建s2之前可能有很多String对象
//不可能遍历这些对象
//看看哪个对象保存的内容是hello
//s2再去共用空间 —— 只有确保内容一致时，才能共用空间 —— 复制或赋值时
string s2("hello");
```

```C++
{
private:
    // 内部类--->处理下标访问运算符的读写逻辑
    class CharProxy
    {
    public:
        CharProxy(CowString & cowString, size_t index)
        : m_self(cowString)
        , m_index(index)
        {}
        //operator<< 读操作 cout << s1[0] --> charProxy-->CowString-->m_pStr-->char
        //友元函数方式进行重载
        friend
        ostream & operator<<(ostream & os ,const CharProxy & proxy);

        //operator= 写操作 s[0]='A' char = char
        // []-->proxy-->cowString-->m_pStr-->char   =  char
        // 成员函数重载
        char & operator=(const char & ch);
    private:
        CowString & m_self;
        size_t m_index;
    };
    
    //......
}
```

C++ 的访问权限是按类划分的，不是按对象划分的。
同一个类的成员函数，可以访问该类的任何一个对象的私有成员。
所以，这里的rhs可以直接访问m_pstr。
m_pstr = rhs.m_pstr;      //可以这样写。直接访问rhs中的m_pstr。
public / private 限制的是"不同类能不能访问"，不限制"同一个类的不同对象能不能互相访问"。

### 5.7.3：短字符串优化（SSO）
![[短字符串优化.png]]
当字符串的字符数小于等于15时， buffer直接存放整个字符串；当字符串的字符数大于15时， buffer 存放的就是一个指针，指向堆空间的区域。这样做的好处是，当字符串较小时，直接拷贝字符串，放在 string内部，不用获取堆空间，开销小。

一个字符串类型的对象，他的大小为32字节。
有些地方实现，用的是24字节。

![[不同平台字符串对象大小.png]]
#### 32字节实现
内部有：一个char指针，一个size_t变量，一个union。
```C++
struct basic_string 
{
    char* _M_p;              // 指向数据
    size_t _M_string_length; // 当前长度
    union 
    {
        char _M_local_buf[16]; // SSO 缓冲区
        size_t _M_allocated_capacity; // 堆分配时的容量
    };
};
```
char指针：
    占用8字节，指向数据。当短字节时，指向内部的SSO缓冲区。当为长字节时，指向堆区的数据内存。
size_t变量：
    用来记录当前字符串的长度。
union：
    当字符串长度在15个字节以内，为SSO缓冲区。
    当字符串长度大于15个字节，为一个size_t对象，存放堆区给字符串分配的容量。

#### 24字节实现
核心在于用**一个 `union` 巧妙地复用了同一块内存**，让字符串对象在“长字符串”和“短字符串 (SSO)”两种模式间自由切换。
```C++
union 
{
    struct // 长字符串视图（24 字节）
    {  
        char*     data_;    // 8 字节：指向堆内存
        size_t    size_;    // 8 字节：当前长度
        size_t    cap_;     // 8 字节：容量（最低位为 1 标记“长模式”）
    } long_;
    
    struct // 短字符串视图（24 字节）
    {  
        unsigned char size_;  // 1 字节：长度 << 1（最低位为 0 标记“短模式”）
        char data_[23];       // 23 字节：内联字符缓冲区
    } short_;
};
```
